Linux相关

2026-09-21/更新于 2026-10-01

Linux 是一个开源的、类 Unix 的操作系统内核。平时我们说的 Linux 系统通常指 Linux 内核+GNU 工具包+软件包管理器+桌面环境等 组成的完整操作系统，也叫 GNU/Linux。

Linux 的可移植性极强，从嵌入式设备、路由器到服务器，再到超级计算机都能运行。普通人极少直接打开 Linux 桌面，但几乎离不开背后运行的 Linux。

常见发行版：Ubuntu、Debian、Fedora、CentOS、Red Hat、Arch、openSUSE、Kali 等。不同发行版在软件包管理、更新方式和用途上有所不同。

什么是 GNU

GNU 是一个自由软件项目，递归缩写为 “GNU’s Not Unix”。其开发了大量操作系统必需的用户空间软件：

  • 核心命令行工具：ls、cp、mv 等，属于 GNU Coreutils
  • Shell：bash
  • 编译器：GCC
  • C 库：glibc
  • 调试器：GDB
  • …

GNU 自己也设计了一个内核，叫 GNU Hurd，但长期没有真正普及。后来 Linux 内核出现，和 GNU 的用户空间工具组合在一起，形成了一个完整可用的自由操作系统。

“万物皆文件”

在 Linux 中，很多不同类型的资源都被抽象为文件系统里的对象，通过统一的文件接口来访问。

根目录下的层级结构严格遵循文件系统层级规范，将底层内核、管理命令、用户数据、虚拟状态与第三方软件严格隔离开。

引导启动与基础二进制

  • /boot：作为系统启动的核心目录，包含 Linux 内核镜像、初始内存盘镜像以及引导加载程序等，系统启动完成后通常处于只读状态。

  • /bin、/sbin：可执行程序目录，实际位置在 /usr/bin 、 /usr/sbin。

    传统意义上，/bin 中存放的是系统级工具（GNU Coreutils），不混杂第三方程序。但后来发行版将 /bin 软链至 /usr/bin，而 /usr/bin 本来就装了大量发行版打包的第三方软件，所以目前来说，/bin 下是二进制软件共存的目录。

    第三方软件怎么放才规范？

    • 发行版仓库安装的第三方： /usr/bin，由包管理器管理
    • 自己编译安装的： /usr/local/bin
    • 独立大型软件：/opt
    • 用户私有：~/.local/bin

  • /lib、/lib64：动态链接库目录，实际位置在 /usr/lib、/usr/lib64。

    动态链接库是一种程序运行时才按需加载的共享代码包，允许多个程序共用同一份功能，从而大幅节省内存空间（修改链接包本身无需重新编译主程序，即具有热更新特性）

配置文件与用户工作区

  • /etc：系统级全局配置文件目录。存放所有系统服务、网络协议和守护进程的纯文本配置文件（如 /etc/passwd、/etc/fstab、/etc/hosts、/etc/nginx 等）
  • /root：超级管理员的专属家目录。
  • /home：普通用户的家目录存储区，系统为每一个普通用户分配一个子目录，存放用户的个人数据及配置文件（如 ~/.bashrc）

虚拟、设备与临时文件系统

  • /dev：设备节点目录，映射系统中的硬件设备，如硬盘分区 /dev/sda1、终端设备 /dev/tty 以及特殊伪设备 /dev/null（读返回 EOF，写被丢弃）、/dev/zero（读返回 NUL 字节，写被丢弃）、/dev/urandom（生成伪随机字节）

  • /proc：内核与进程状态镜像，以文件形式呈现运行中进程的内存与运行数据（/proc/[PID]），以及系统软硬件实时统计（如 /proc/meminfo、/proc/cpuinfo。但是更常用的替代是 free -h 和 lscpu）

  • /sys：将内核中识别到的物理设备、驱动程序、总线（PCI、USB）按统一层次树呈现，支持直接读写控制硬件参数。

  • /tmp：全局临时文件目录，供所有程序和用户存放短期临时数据。

  • /mnt 与 /media：外部存储挂载点。

应用程序与可变状态

  • /usr：系统资源目录，系统安装的绝大多数软件实体所在地。
  • /var：可变数据目录，用于存储运行时不断变化的数据（日志、缓存、队列、数据库等）
    • /var/log：系统日志
    • /var/cache：包管理器缓存
    • /var/lib：服务数据与数据库
    • /var/www/html：Debian/Ubuntu 系的 Apache 默认主站点目录
  • /opt：可选附加应用软件包，一般用于存放独立的第三方闭源或商业文件（如 Chorme、Docker 等）

权限

用户与用户组

Linux 把系统内的实体抽象为 UID（用户）和 GID（用户组），内核鉴权时只看 ID。

root 作为超级管理员拥有最高权限，UID 为 0，不受任何限制；普通用户 UID 一般从 1000 开始，只能动自己权限范围内的东西。此外还有系统用户，供后台守护进程使用（UID 1~999）

输入 id，查看当前用户的 UID、主组 GID 以及附加组。whoami 查看当前用户名。

用户组用来把一批用户打包，统一管理权限。输入 groups 查看当前用户加入了哪些组。

UGO 文件权限模型

UGO = 按“你是谁”把人分成三类（属主 U，属组 G，其它人 O），每类一份 rwx（可读 r，可写 w，可执行 x）

系统判断时只认一类：若既是属主也是属组，则只看 U 权限（即使 G 权限大于 U）

想查看文件权限模型使用 ls -l，更改使用 chmod，换属主用 chown：

  • ls -l file.txt

数字表示法

用八进制表示。对于 rwx-，r = 4, w = 2, x = 1, - = 0，全部加起来能够唯一确定三种用户的权限。

比如 rw-r--r--，U 的分值是 6，G 的分值是 4，O 的分值也是 4，连起来就是 644（普通文件默认）

目录的 x 意味着能否进入此目录。

常见有：

  • 644：rw- | r-- | r--，普通文件
  • 600：rw- | --- | ---，常见于私钥文件
  • 755：rwx | r-x | r-x，可能是目录或可执行文件
  • 700：rwx | --- | ---，只有主人可进入的目录，比如 ~/.ssh
  • 777：rwx | rwx | rwx，最省事的一集
